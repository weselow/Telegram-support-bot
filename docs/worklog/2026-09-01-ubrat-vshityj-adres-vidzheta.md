# Убрать вшитый адрес сервера из виджета чата

**Дата:** 2026-09-01
**Задача:** Telegram-support-bot-f6a
**Ветка:** `bd-Telegram-support-bot-f6a`

## Что сделано

Из виджета убран боевой домен, который был записан в исходниках как запасное
значение (`chat-widget/src/types/config.ts`, `chat-widget/esbuild.config.js`).
Теперь `DEFAULT_CONFIG` содержит только оформление и поведение, а адреса сервера
(`apiUrl`, `wsUrl`, `baseUrl`) приходят снаружи: из адреса самого скрипта, из
`window.DellShopChatConfig` или из `data`-атрибутов тега. В сборку не попадает
ни одного адреса — проверено поиском по собранному `dist/chat-widget.js`.

Если ни один источник адрес не дал, виджет не запускается: `resolveConfig`
бросает исключение с текстом `MISSING_SERVER_URLS_MESSAGE`, где сказано, что
сломано и как чинить.

Попутно:

- `mergeConfig` из `config.ts` удалена (её никто не вызывал) — вместо неё и
  поверхностного слияния в конструкторе `ChatWidget` теперь одна `resolveConfig`.
  Она сливает вложенные `responsive` и `theme` с умолчаниями; раньше передача
  `responsive: { breakpoint: 500 }` теряла `mobile`/`desktop`, и `resolveVariant`
  возвращала `undefined`.
- `PartialWidgetConfig` перестал требовать вложенные группы целиком.
- Автозапуск (`chat-widget/src/index.ts`) больше не пишет в консоль на каждой из
  пяти попыток — сообщение выводится один раз, после последней.
- Страница разработчика `chat-widget/dev/index.html` вызывала `DellShopChat.init()`,
  а такого метода нет — заменено на `window.DellShopChatConfig`, заданный до тега
  скрипта.
- `WIDGET_VERSION` поднят до `0.1.13`.
- Из текущей документации, `.env.example`, комментария в `deploy.yml` убраны
  упоминания бывшего боевого домена — вместо него нейтральные `example.com`,
  `example.org`, `example.net`.

## Почему так

Адрес виджет вычисляет из адреса своего скрипта с версии 0.1.11, поэтому вшитое
значение срабатывало только когда тег скрипта найти не удалось. В этом случае оно
не спасало, а вредило: виджет молча стучался в домен, которого уже нет, вместо
того чтобы сказать, что настроен неправильно. Плюс единой сборке для сторонних
сайтов (эпик `Telegram-support-bot-9u9`) нельзя знать один боевой домен.

Второй вариант — требовать переменную сборки `SUPPORT_DOMAIN` без значения по
умолчанию — отклонён: домен всё равно остался бы вшитым в образ, только через
`Dockerfile`, GitHub Actions и настройки Coolify.

## Что проверять первым при поломке

1. **Виджет не появился на сайте.** Открыть консоль браузера. Сообщение
   `[ChatWidget] Cannot determine the support server address` означает, что тег
   скрипта не нашёлся. Самая частая причина — плагин кэширования склеил скрипт
   виджета с остальными в один файл; такому плагину надо запретить трогать этот
   скрипт. Запасной путь — задать `window.DellShopChatConfig = { apiUrl, wsUrl,
   baseUrl }` до загрузки виджета.
2. **Виджет появился, но запросы уходят не туда.** Смотреть, откуда загружен
   скрипт: адреса выводятся из него (`chat-widget/src/utils/script-origin.ts`).
   Если склейка всё же произошла, `document.currentScript` укажет на файл на
   домене клиента — виджет не упадёт, а будет стучаться на сайт клиента.
3. **Собранный файл.** `cd chat-widget && pnpm run build:prod`, затем поиск
   любого домена в `dist/chat-widget.js` — там не должно быть ни одного.

## Что осознанно не тронуто

- Бэкендовая переменная окружения `SUPPORT_DOMAIN` (проверка источников CORS) —
  это другая вещь с тем же именем.
- `Dockerfile`, GitHub Actions, настройки Coolify — переменная виджету и не
  передавалась, менять нечего.
- Бывший боевой домен в бэкендовых тестах и комментариях `src/utils/cors.ts` —
  там имена доменов несут смысл проверки (родительский домен, поддомен,
  посторонний домен), слепая замена сломает смысл. Отдельная задача.
- Исторические записи в `docs/bugs/`, `docs/solutions/`, `docs/worklog/`,
  `connections.md`, `msg.txt` — они описывают то, что действительно было.
- Глобальное имя `DellShopChat` и пакет `@dellshop/chat-widget` — переименование
  сломает все страницы, где виджет уже подключён.
- `public/chat-widget/index.html` — устаревшая копия страницы разработчика,
  подключает `/chat-widget.js` (не тот путь) и вызывает несуществующий
  `DellShopChat.init`. Была сломана и до этой задачи. Отдельная задача.
