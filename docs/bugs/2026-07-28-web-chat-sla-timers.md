# Напоминания по срокам не ставились для обращений из виджета

**Дата:** 2026-07-28
**Источник:** Telegram-support-bot-e1g

## Проблема

Обращение, созданное через виджет на сайте, не получало ни первого напоминания (10 минут),
ни второго (30 минут), ни эскалации (2 часа). Обнаружено при живой проверке после переезда
на Coolify: обращение из виджета создало тему 283, но в Redis (`bull:sla:delayed`) не появилось
ни одной отложенной задачи.

## Причина

Таймеры сроков заводились только в обработчиках Телеграма — `src/bot/handlers/onboarding.ts:147`
(новое обращение) и `src/bot/handlers/message.ts:73` (повторное открытие закрытого).
В `src/services/web-chat.service.ts` вызова `startSlaTimers` не было вообще, хотя тема для
веб-обращения создаётся именно там.

Снятие таймеров при этом работало и для веб-обращений: `src/bot/handlers/support.ts:119`
находит обращение по номеру темы независимо от канала. То есть механика снятия рассчитывала
на таймеры, которых никто не заводил — это упущение, а не замысел.

## Решение

Блок создания темы был продублирован в `sendMessage` и `sendFile` почти дословно (~27 строк
в каждом). Вынесен во вспомогательную функцию `ensureTopic(user, sessionId)`: она возвращает
существующую тему или создаёт новую, отправляет карточку обращения, приветственные сообщения
и заводит таймеры сроков. Одна точка вместо двух копий.

## Изменённые файлы

- `src/services/web-chat.service.ts` — добавлена `ensureTopic`, из `sendMessage` и `sendFile`
  убрано дублирование, добавлен вызов `startSlaTimers`
- `src/services/__tests__/web-chat.service.test.ts` — тесты на заведение таймеров при создании
  темы и на отсутствие повторного заведения при существующей теме (для сообщения и для файла);
  внешний `describe` переименован в `web-chat.service` по соглашениям проекта

## Важно для разработчика

Напоминания по срокам — это отсчёт времени до **первого ответа сотрудника**. Заводятся один раз
при создании обращения, снимаются при первом сообщении сотрудника в тему. При обычных
последующих сообщениях клиента они не перезаводятся ни в Телеграме, ни в виджете.

Рядом остаётся незакрытая проблема: веб-канал вообще не меняет статусы обращения
(`autoChangeStatus` из `web-chat.service.ts` не вызывается). Из-за этого сообщение из виджета
не переводит обращение из «Ждём клиента» в «В работе», не снимает таймер автозакрытия и не
открывает заново закрытое обращение. Заведена отдельная задача Telegram-support-bot-cwg.
