# Виджет чата не появлялся на dellshop.ru: адрес сервера был вшит в сборку

**Дата:** 2026-07-29
**Источник:** Telegram-support-bot-plr

## Проблема

На dellshop.ru не было иконки чата. Виджет на сайте подключён и включён:

```
https://chat.dellshop.ru/chat-widget/chat-widget.js?theme=chatgpt&variant=drawer
```

## Причина

Домен `chat.dellshop.ru` не обслуживается ни на одном сервере:

| Проверка | Результат |
|----------|-----------|
| DNS `chat.dellshop.ru` | `31.128.35.197` |
| DNS `dellshop.ru`, `support.dellshop.ru`, `rackparts.ru` | `188.235.139.236` |
| HTTPS на 31.128.35.197 | запасной сертификат `TRAEFIK DEFAULT CERT` |
| HTTP на 31.128.35.197 | `404` от Traefik |
| Обращение к 188.235.139.236 с именем `chat.dellshop.ru` | тот же запасной сертификат |

A-запись указывает на сервер, где приложения нет, а на том сервере, где оно есть,
домен в Coolify не заведён — там настроен только `beforetheygo.web.codecitadel.ru`.
Браузер обрывал загрузку на ошибке сертификата, скрипт не выполнялся.

Само приложение при этом было здорово: `/health` отвечал `200`, виджет и стили
отдавались по адресу `beforetheygo.web.codecitadel.ru`, вебсокет проходил через
прокси, а CORS уже разрешал `Origin: https://dellshop.ru`.

Переехать на рабочий домен одной правкой на сайте было нельзя: адрес сервера
вшивался в виджет **на этапе сборки** (`chat-widget/src/types/config.ts` →
`esbuild.config.js` → этап `widget-builder` в `Dockerfile`). Из ссылки на скрипт
виджет читал только `theme`, `variant`, `autoOpen`, `sound`, `position`; адреса
API, вебсокета и стилей брались только из `data`-атрибутов или
`window.DellShopChatConfig`. Админка сайта хранит один голый адрес без атрибутов —
значит скрипт загрузился бы с нового домена, а за данными пошёл бы на мёртвый старый.

## Решение

Виджет определяет адреса сервера по адресу, с которого загружен его собственный
скрипт. Смена домена стала правкой одной строки на сайте — без пересборки и выкатки.

Ключевая деталь: `document.currentScript` захватывается **на верхнем уровне модуля**.
Он заполнен только во время синхронного выполнения скрипта, а настройки разбираются
позже (по событию `DOMContentLoaded` и на повторных попытках), когда он уже `null`.
Сайт вставляет скрипт отложенно, поэтому без раннего захвата этот путь не работал бы
вовсе и всегда срабатывал бы запасной поиск по документу.

Запасной поиск (`script[src*="widget"], script[src*="chat"]`, последнее совпадение)
сохранён, но он ненадёжен: под него подходит любой чужой скрипт со словом «chat» в
адресе — например счётчик посещаемости.

Приоритеты настроек, от низшего к высшему:
адрес скрипта → `window.DellShopChatConfig` → параметры ссылки → `data`-атрибуты.

Домен, вшитый при сборке, остался запасным значением на случай, когда тег скрипта
найти не удалось. `Dockerfile` и `deploy.yml` не менялись.

## Изменённые файлы

- `chat-widget/src/utils/script-origin.ts` — новый: вывод `apiUrl`/`wsUrl`/`baseUrl` из адреса скрипта, поиск своего тега
- `chat-widget/src/utils/script-config.ts` — новый: сборка настроек из тега с учётом приоритетов
- `chat-widget/src/index.ts` — захват `document.currentScript` на верхнем уровне; разбор настроек вынесен в `utils/`
- `chat-widget/src/widget.ts` — `WIDGET_VERSION` 0.1.10 → 0.1.11
- `chat-widget/src/__tests__/utils/script-origin.test.ts` — новый: 15 проверок
- `chat-widget/src/__tests__/utils/script-config.test.ts` — новый: 11 проверок
- `docs/modules/chat-widget/README.md` — раздел подключения переписан

## Важно для разработчика

- **Протокол вебсокета выводится из протокола скрипта:** `https` → `wss`, `http` → `ws`.
  Прежняя сборка всегда подставляла `wss:`, из-за чего локальная разработка на
  `http://localhost:3500` получала неработающий `wss://localhost:3500/ws/chat`.
- **`baseUrl` — это каталог скрипта, а не корень сайта.** Скрипт в
  `/chat-widget/chat-widget.js` даёт `baseUrl` = `<домен>/chat-widget`, откуда грузятся
  `base.css`, `modal.css`, `drawer.css` и темы. Если положить скрипт в другой каталог,
  стили должны переехать вместе с ним.
- **Проверено в браузере:** страница со скриптом с `http://localhost:3999` дала
  `apiUrl=http://localhost:3999`, `wsUrl=ws://localhost:3999/ws/chat`,
  `baseUrl=http://localhost:3999/chat-widget`; все запросы ушли на localhost,
  ни одного на вшитый домен, кнопка чата отрисовалась.

## Что осталось сделать вне репозитория

На сайте dellshop.ru поменять адрес скрипта на рабочий домен:

```
https://beforetheygo.web.codecitadel.ru/chat-widget/chat-widget.js?theme=chatgpt&variant=drawer
```

Либо вернуть к жизни `chat.dellshop.ru`: направить A-запись на `188.235.139.236`
и добавить домен приложению в Coolify — тогда Traefik выпустит сертификат.
Свой поддомен предпочтительнее: адрес чужого домена виден посетителям сайта
в сетевых запросах.
