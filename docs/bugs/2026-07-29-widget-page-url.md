# В карточке тикета виден только домен вместо страницы

**Дата:** 2026-07-29
**Источник:** Telegram-support-bot-76e

## Проблема

В карточке тикета в группе поддержки поле «Источник» показывало корень сайта
(`https://server360.ru/`), хотя человек писал с конкретной страницы каталога.
Сотрудник поддержки не видел, что именно смотрел посетитель.

## Причина

Две независимые причины, обе давали один и тот же результат.

1. Адрес брался из заголовка `Referer` запроса `POST /api/chat/init`
   (`src/http/routes/chat.ts`). Браузер по политике по умолчанию
   `strict-origin-when-cross-origin` укорачивает `Referer` до адреса домена,
   когда запрос идёт на другой домен. Виджет стоит на сайте клиента, а запрос
   уходит на домен бота — точный адрес страницы до сервера не доезжал вообще.

2. `sourceUrl` записывался только при создании пользователя
   (`initSession` → `createWebUser`). Сессия заводится при первом заходе на сайт,
   а карточка тикета создаётся при первом сообщении. Посетитель заходил на
   главную, переходил на страницу товара и писал оттуда — в карточке всё равно
   оставалась главная.

## Решение

Виджет сам знает адрес страницы и передаёт его явно, `Referer` остался запасным
вариантом:

1. `HttpClient.init()` отправляет в теле запроса `{ pageUrl: window.location.href }`.
2. Маршрут `/api/chat/init` берёт адрес из тела, **только если** его домен
   совпадает с заголовком `Origin` запроса — иначе адрес в карточке можно было бы
   подделать произвольной строкой. Без совпадения (и без `Origin`) используется
   прежний `Referer`, который при запросе внутри одного домена не укорачивается.
3. `initSession` обновляет `sourceUrl` у существующего пользователя, пока топик
   ещё не создан (`topicId === null`). После создания топика адрес не меняется,
   чтобы не переписывать историю обращения.
4. Карточка тикета переведена с разметки Markdown на HTML с экранированием всех
   внешних данных. Без этого исправление ломало бы карточку: Telegram разбирает
   Markdown и на адресе вида `/catalog/dell_poweredge_r740` считает одиночное
   подчёркивание началом курсива, не находит парного и отвечает ошибкой — то
   есть карточка не отправилась бы вовсе. Раньше это не проявлялось только
   потому, что до сервера доезжал один домен без пути. Заодно закрылся тот же
   риск для имени посетителя и города.

Рассмотренные и отклонённые варианты: просить владельцев сайтов ставить
`<meta name="referrer">` (изменения на каждом сайте, легко потерять при
переделке сайта) и хранить историю всех посещённых страниц (заметно больше
работы ради того же одного адреса в карточке).

## Важно для разработчика

- Адрес из тела запроса — данные от клиента. Доверять им можно только после
  сравнения домена с заголовком `Origin`; проверка живёт в `resolvePageUrl`
  вместе с ограничением длины (1000 символов) и списком допустимых схем.
- Карточка тикета теперь HTML. Любое новое поле в `formatCardText` надо
  пропускать через `escapeHtml`, иначе Telegram откажется отправлять сообщение.
- Переход на Telegram через `/ask-support` страдает от той же особенности
  браузера, но чинится иначе — адрес надо передавать в самой ссылке. Заведено
  отдельной задачей Telegram-support-bot-jkl.
- Напоминания SLA и личные сообщения администраторам по-прежнему уходят с
  разметкой Markdown и без экранирования имён (`src/jobs/sla.worker.ts`,
  `src/services/group.service.ts`). Заведено отдельной задачей
  Telegram-support-bot-8pg.
- Собранные файлы виджета в git не хранятся, образ собирает их сам
  (`Dockerfile`, шаг `widget-builder`). Поднимать `WIDGET_VERSION` при изменениях
  в `chat-widget/` обязательно — по ней видно, какая версия у посетителя.
