# Образ приложения весил 784 МБ

**Дата:** 2026-07-29
**Источник:** Telegram-support-bot-n6t

## Проблема

Образ `ghcr.io/weselow/telegram-support-bot` занимал 784 МБ. На боевом сервере оставалось 1,1 ГБ свободного места, а при выкатке нужно место одновременно под старый и новый образ — выкатка могла упасть.

Заодно вскрылись две поломки локальной сборки: `docker compose build` не проходил вовсе, а собранный на Windows образ не запускался.

## Причина

**Основная — `chown -R nodejs:nodejs /app` последней строкой Dockerfile.** Смена владельца затрагивает все файлы, поэтому Docker записывает в новый слой полную копию каталога `/app` — 359 МБ. Хуже того, слой пересобирается при каждой выкатке: соседние версии образа не делят ни одного тяжёлого слоя, и каждая выкатка добавляет на диск ещё 359 МБ.

**Сопутствующие:**

- `typescript` (22 МБ) попадал в рабочий образ, потому что `@prisma/client` объявляет его необязательной сопутствующей зависимостью (peer dependency), а он есть в `devDependencies` — pnpm тянет такие пакеты и при установке `--prod`. Ни `auto-install-peers=false`, ни `pnpm prune --prod` от этого не спасают;
- `@prisma/client` везёт компиляторы запросов (wasm) для пяти СУБД — 19 МБ лишнего при одном PostgreSQL;
- Prisma CLI копировался из этапа сборки отдельным слоем на 19,7 МБ, хотя pnpm уже клал его в хранилище;
- `.dockerignore` исключал только корневой `node_modules`: шаблон без `**/` в Docker не применяется к вложенным каталогам. Поэтому `chat-widget/node_modules`, собранный под Windows, уезжал в контекст сборки и затирал зависимости внутри образа — этап сборки виджета падал;
- `docker-entrypoint.sh` в рабочем каталоге на Windows имел перевод строки CRLF. Символ возврата каретки попадал в строку запуска интерпретатора, и контейнер падал с `no such file or directory`. В GitHub Actions этого не было видно — там файлы выгружаются с LF.

## Решение

- владелец файлов остаётся root, приложение работает под `nodejs` и только читает — `chown -R` убран;
- лишнее удаляется в том же слое `RUN`, что и установка зависимостей: отдельная команда не уменьшила бы образ, файлы остались бы в предыдущем слое;
- вместо копирования Prisma CLI создаётся ссылка на пакет в хранилище pnpm, а `test -x` в том же слое ломает сборку, если ссылка перестанет вести на исполняемый файл;
- `.dockerignore` переписан на шаблоны с `**/`, добавлены `.worktrees`, `.volumes`, `.beads`, `credentials.txt`;
- `.gitattributes` фиксирует LF для `*.sh`.

Сумма слоёв: 934 → 494 МБ. На сервере ожидается около 415 МБ вместо 784 МБ. Повторная выкатка без изменения зависимостей добавляет на диск около 3 МБ.

## Изменённые файлы

- `Dockerfile` — убран `chown -R`, удаление лишнего перенесено в слой установки, ссылка на Prisma CLI вместо копирования
- `docker-entrypoint.sh` — запуск Prisma CLI напрямую через `node`, обёртки `.bin/prisma` в рабочем образе нет
- `.dockerignore` — шаблоны с `**/`, исключены рабочие копии и данные контейнеров
- `.gitattributes` — LF для `*.sh`
- `docs/deployment/README.md` — раздел про место на диске

## Важно для разработчика

- Удаление файлов отдельной командой `RUN` не уменьшает образ — только в том же слое, где они появились.
- То же и с базовым образом: удалять из `node:22-alpine` пакетные менеджеры npm и yarn (23 МБ) бесполезно, слой чужой.
- Перед первой выкаткой уменьшенного образа старые образы на сервере надо удалить вручную — общих слоёв у них с новым нет.
- В рабочем образе нет `node_modules/.bin/prisma`: pnpm не создаёт обёртки запуска для сопутствующих зависимостей. Prisma CLI вызывается как `node node_modules/prisma/build/index.js`.
